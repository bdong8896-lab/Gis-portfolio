QGIS·ArcGIS에서 좌표계가 없는 데이터에 좌표계 지정하기

.prj가 없어 좌표계가 "알 수 없음"인 셰이프파일을 QGIS·ArcGIS에서 열 때, 좌표계를 지정하는 것과 재투영하는 것의 차이와 올바른 순서를 정리했습니다.

2026.10.13 작성

이런 증상이라면

  • 레이어를 열었는데 좌표계가 "알 수 없음(Unknown)"으로 표시된다.
  • 다른 레이어와 겹치지 않고 멀리 떨어진 곳에 뜨거나 화면에 안 보인다.
  • 좌표계를 바꿨는데 위치가 더 틀어졌다.

핵심: "지정"과 "재투영"은 전혀 다른 작업

좌표계 지정(정의)재투영(변환)
하는 일좌표 값은 그대로 두고 "이 값은 이 좌표계"라고 이름표를 붙임좌표 값을 다른 좌표계의 값으로 계산해 바꿈
쓸 때.prj가 없거나 잘못되어 좌표계 정보가 틀렸을 때이미 좌표계가 맞는 데이터를 다른 좌표계로 옮길 때
QGIS레이어 CRS 설정 (Set Layer CRS)레이어 재투영 (Reproject Layer) / 다른 CRS로 내보내기
ArcGISDefine Projection (투영 정의)Project (투영)

좌표계 정보가 없는 데이터에 재투영을 먼저 걸면 이름표를 모르는 채로 값을 바꾸게 되어 위치가 엉뚱해집니다. 순서는 항상 ① 지정 → ② 필요하면 재투영입니다.

올바른 순서

  1. 어떤 좌표계인지 추정합니다. 좌표 값의 모양으로 후보를 좁힙니다. 여섯 자리 숫자쌍이면 중부원점 계열(5181·5186·5174)이 흔하고, 값이 경위도처럼 작으면 4326입니다.
  2. 후보를 지정해 보고 지도에서 확인합니다. 위치를 아는 배경지도(위성영상, 행정구역)와 겹치는지 눈으로 봅니다.
  3. 맞는 좌표계를 찾았으면 그대로 지정(정의)해 저장합니다. 이때는 값이 바뀌지 않습니다.
  4. 다른 좌표계(예: 웹 지도용 4326)로 쓰려면 그다음에 재투영합니다.

좌표계 후보별 특징과 숫자 판별법은 좌표계가 어긋날 때: EPSG:5181과 3857 다루기에 정리해 두었습니다.

5181과 5186이 헷갈릴 때

두 좌표계는 Y 가산값만 달라서 한쪽을 다른 쪽으로 잘못 지정하면 정확히 100km 어긋납니다. 후보 두 개를 번갈아 지정해 보면서 배경지도와 맞는 쪽을 고르면 됩니다. 구 Bessel(5174) 자료라면 변환할 때 측지 변환(datum transformation) 방식 선택에 따라 수백 m 차이가 날 수 있으니, 변환 대화 상자에서 사용한 방식을 확인하세요.

흔한 실수

  • 이중 변환: 이미 맞는 좌표계에 재투영을 두 번 거는 경우. 변환 이력을 기록해 둡니다.
  • 화면 좌표계와 레이어 좌표계를 혼동: 프로젝트(지도 창) 좌표계를 바꾼 것은 데이터 자체를 바꾼 것이 아닙니다.
  • .prj만 믿음: .prj가 있어도 잘못 적혀 있는 경우가 있습니다. 한 번은 지도에서 직접 확인하세요.

웹 지도로 가져갈 때

웹 지도(OpenLayers, 카카오맵 등)에서 쓸 GeoJSON은 보통 EPSG:4326(경도, 위도)으로 내보냅니다. 위 순서로 좌표계를 먼저 바로잡은 다음 4326으로 재투영해서 내보내면 됩니다.

# 좌표계 5186 데이터를 4326 GeoJSON으로 변환
ogr2ogr -f GeoJSON -s_srs EPSG:5186 -t_srs EPSG:4326 out.geojson in.shp

여기서 -s_srs가 "지정"에 해당하고, -t_srs가 "재투영"입니다.

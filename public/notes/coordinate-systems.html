좌표계가 어긋날 때: EPSG:5181과 3857 다루기

국내 지도 데이터와 웹 지도를 함께 쓸 때 위치가 수십~수백 미터씩 밀리는 원인과, 좌표계를 정리하는 방법을 OpenLayers 코드와 함께 설명합니다.

2026.10.13 작성

이런 증상이라면

  • 같은 필지인데 레이어끼리 수십~수백 m씩 밀려 보인다.
  • 점이 한국이 아니라 바다 한가운데나 (0, 0) 근처에 찍힌다.
  • WMS는 맞는데 WFS나 GeoJSON만 위도와 경도가 뒤집힌 것처럼 보인다.

거의 모든 경우 원인은 하나입니다. 데이터의 좌표계를 코드가 잘못 가정하고 있다는 것입니다.

먼저 알아둘 좌표계

EPSG이름단위 · 특징
4326WGS84 경위도도(degree). OpenLayers에서는 [경도, 위도] 순서
3857웹 메르카토르m. 구글·OSM 같은 타일 지도의 기본
5181Korea 2000 / 중부원점m. GRS80 타원체, 국내 지도 서비스에서 흔히 쓰는 TM
5186Korea 2000 / 중부원점(Y 600,000)5181과 같은 계열이지만 Y 가산값이 다름
5179Korea 2000 / UTM-Km. 전국을 한 장으로 다루는 좌표계
5174구 Bessel 중부원점m. 오래된 지적·건물 자료에서 자주 보임

밀리는 원인 세 가지

1. 좌표계를 지정하지 않고 가정했다

5181과 5186은 모양이 거의 같지만 Y 가산값이 각각 500,000과 600,000입니다. 한쪽 값을 다른 쪽으로 읽으면 정확히 북쪽(남쪽)으로 100km 어긋납니다. 눈으로는 "엉뚱한 곳"이라 바로 알 수 있습니다.

2. 측지계(datum)가 달라 변환 변수가 빠졌다

구 Bessel 기반(5174)과 GRS80 기반(5181 등)은 기준 타원체 자체가 다릅니다. 변환 정의에 이동 변수(towgs84)가 없으면 수백 m 안팎의 오차가 남습니다. "거의 맞는데 건물 하나만큼 틀리는" 증상은 대부분 이 경우입니다.

3. 축 순서가 뒤집혔다

EPSG:4326을 쓰는 WMS 1.3.0은 규격상 위도, 경도 순서이고, GeoJSON과 OpenLayers의 4326은 경도, 위도 순서입니다. 같은 4326이라도 서비스마다 다르니 요청 파라미터(BBOX)를 직접 확인해야 합니다.

OpenLayers에서 정리하는 방법

proj4에 좌표계 정의를 등록한 뒤, 변환은 반드시 한 곳에서만 합니다.

import proj4 from 'proj4';
import {register} from 'ol/proj/proj4';
import {transform} from 'ol/proj';

// 5181: 중부원점, GRS80
proj4.defs('EPSG:5181',
  '+proj=tmerc +lat_0=38 +lon_0=127 +k=1 +x_0=200000 +y_0=500000 ' +
  '+ellps=GRS80 +units=m +no_defs');
register(proj4);

const lonlat   = transform([x, y], 'EPSG:5181', 'EPSG:4326');
const mercator = transform([x, y], 'EPSG:5181', 'EPSG:3857');

GeoJSON을 읽을 때는 데이터가 어떤 좌표계인지와 화면이 어떤 좌표계인지를 둘 다 알려줍니다.

import GeoJSON from 'ol/format/GeoJSON';

const features = new GeoJSON().readFeatures(data, {
  dataProjection: 'EPSG:5181',     // 파일 안의 좌표계
  featureProjection: 'EPSG:3857',  // 화면(지도 뷰)의 좌표계
});

원칙: 저장은 한 가지, 변환은 한 곳

  • 서버와 DB에는 한 가지 좌표계로만 저장합니다(보통 4326 또는 데이터의 원본).
  • 화면에 그릴 때만 3857로 바꿉니다. 코드 여기저기에서 변환하면 두 번 변환되는 사고가 납니다.
  • 좌표 값에 좌표계 이름을 변수명에 붙입니다(x5181, lonLat). 몇 달 뒤의 나를 위한 메모입니다.

숫자만 봐도 알 수 있는 진단법

값의 모양의심할 좌표계
경도 124~132, 위도 33~394326 (경위도)
x 약 1,380만~1,470만 / y 약 390만~470만3857 (웹 메르카토르)
x, y 모두 여섯 자리(수십만) 숫자5181·5186·5174 같은 중부원점 계열
x가 수십만~백만대, y가 백만대 이상5179 (UTM-K)

값의 자릿수만 봐도 후보가 거의 좁혀집니다. 그다음 위치를 아는 지점 하나(예: 시청 좌표)로 변환 결과를 눈으로 확인하면 끝납니다.

좌표를 직접 바꿔 보고 싶다면 자료실의 좌표계 변환기를 사용해 보세요.

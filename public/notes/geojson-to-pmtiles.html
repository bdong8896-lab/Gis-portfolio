큰 GeoJSON을 가볍게: PMTiles로 정적 서비스하기

수십 MB 경계 데이터를 tippecanoe로 PMTiles로 바꿔 서버 없이 정적 파일로 서비스하는 흐름과, OpenLayers 연결, 용량 한도 주의점을 정리했습니다.

2026.10.13 작성

GeoJSON이 느려지는 이유

GeoJSON은 파일 전체를 내려받아 브라우저가 한 번에 파싱합니다. 행정구역이나 필지 경계처럼 데이터가 커지면 첫 화면이 늦게 뜨고, 확대·축소 때마다 버벅임이 생깁니다. 지도에는 지금 보이는 영역과 줌 수준에 필요한 만큼만 있으면 됩니다. 그 방식이 벡터 타일이고, PMTiles는 그 타일들을 파일 하나에 담은 형식입니다.

PMTiles의 장점

  • 타일 서버가 필요 없습니다. 파일 하나를 정적 호스팅에 올리면 됩니다.
  • 브라우저가 HTTP Range 요청으로 필요한 타일 부분만 가져옵니다.
  • OpenLayers, MapLibre 같은 일반 지도 라이브러리에서 쓸 수 있습니다.

변환 순서

1. 입력을 4326 GeoJSON으로 맞추기

tippecanoe는 경위도(EPSG:4326) 좌표를 기대합니다. 셰이프파일이나 다른 좌표계 데이터는 먼저 변환합니다.

# 셰이프파일 → 4326 GeoJSON (한글 속성이 깨지면 인코딩 지정)
ogr2ogr -f GeoJSON -t_srs EPSG:4326 \
  -oo ENCODING=CP949 zones.geojson zones.shp

2. tippecanoe로 PMTiles 만들기

tippecanoe -o zones.pmtiles \
  -l zones -zg \
  --drop-densest-as-needed \
  -y name -y code \
  zones.geojson
  • -l zones : 레이어 이름. 클라이언트에서 같은 이름으로 참조합니다.
  • -zg : 데이터에 맞는 최대 줌을 자동 추정합니다.
  • --drop-densest-as-needed : 타일이 너무 커지면 밀집된 부분부터 덜어 냅니다.
  • -y name -y code : 필요한 속성만 남깁니다. 용량을 줄이는 가장 쉬운 방법입니다.

3. OpenLayers에서 불러오기

import VectorTileLayer from 'ol/layer/VectorTile';
import {PMTilesVectorSource} from 'ol-pmtiles';

const layer = new VectorTileLayer({
  declutter: true,
  source: new PMTilesVectorSource({
    url: 'https://example.com/data/zones.pmtiles',
  }),
});
map.addLayer(layer);

주의할 점

항목내용
호스팅 조건서버가 Range 요청을 지원해야 합니다. 대부분의 정적 호스팅과 오브젝트 스토리지는 지원합니다.
파일 크기 한도Cloudflare Workers 정적 자산은 파일당 25MiB까지입니다. 그보다 크면 R2 같은 오브젝트 스토리지에 올리고 주소로 연결합니다.
CORS다른 도메인에서 불러오면 해당 호스트에 CORS와 Range 관련 헤더 허용이 필요합니다.
정밀도낮은 줌에서는 경계가 단순화됩니다. 면적·길이 계산은 원본 데이터로, 표시는 타일로 나누어 쓰는 것이 안전합니다.
좌표계타일은 4326 입력을 3857로 투영해 만듭니다. 5181 등 원본이 있다면 변환 단계에서 좌표계를 먼저 확인하세요.

언제 쓰면 좋은가

  • 전국 단위 경계처럼 수십 MB 이상이고 속성이 자주 바뀌지 않는 데이터
  • 서버를 운영하지 않고 정적 사이트나 설치형 앱에 지도를 넣고 싶을 때
  • 오프라인 환경에서 파일 하나로 배포해야 할 때

반대로 데이터가 수시로 바뀌거나 속성 조회·편집이 핵심이라면 DB와 API 방식이 맞습니다.
